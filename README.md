# Баговый Офис

## Elevator Pitch

Типичный IT-офис. Пустые столы. Дедлайны горят. Ты — тимлид, и тебе нужно закрывать таски.

Нанимаешь разработчиков, перетаскиваешь задачи из очереди им на стол. Вайбкодер сделает за секунды — но оставит после себя баги. Обычный дев сделает нормально — но пока он пишет, очередь растёт. Баги прилетают обратно в очередь, не отфикшенные вовремя — штраф деньгами. Кодовая база деградирует, всё замедляется. Баланс между скоростью и качеством — это и есть игра.

**Жанр:** Management tycoon.

**Хук:** Вайбкодеры зарабатывают деньги быстро, но медленно убивают проект. Обычные девы держат кодовую базу живой, но стоят дорого и работают медленно. Ты сам закапываешь себе яму — и сам из неё выбираешься.

## Как играется

Игра делится на **спринты**. В начале каждого спринта генерируется пак задач. Состав пака зависит от текущего техдолга. Игрок раскидывает задачи по разрабам перетаскиванием.

Главный ресурс — **деньги**. Зарабатываются за выполненные фичи. Тратятся на найм разрабов и штрафы за баги.

### Разработчики

Три типа. У каждого два стата: `speed` (множитель на время выполнения) и `quality` (множитель на результат).

| | speed | quality |
|---|---|---|
| Вайбкодер | 3.0 | 0.2 |
| Разработчик | 1.0 | 0.8 |
| Бородатый сеньор | 0.5 | 1.5 |

**speed** — во сколько раз быстрее базового времени делается таска.

**quality** влияет на:
- Деньги с фичи: `reward * quality`
- Снижение техдолга от рефакторинга: `debt_reduction * quality`
- Рост техдолга от таски: `base_debt_per_task * (1 - quality)`

Вайбкодер быстро клепает фичи, но гонит техдолг вверх и рефакторить почти не умеет. Сеньор медленный, но делает дорого, долг почти не растёт, рефакторинг работает в полную силу.

### Техдолг

Глобальная метрика состояния кодовой базы (`0.0` — `1.0`).

**Растёт когда:**
- Разраб выполняет любую таску: `base_debt * (1 - quality)`
- Баг истёк не отфикшенным: фиксированный штраф `+0.1`

**Снижается когда:**
- Разраб выполняет таску рефакторинга: `base_reduction * quality`

**Влияние на пак задач спринта:**

| Техдолг | Фичи | Баги | Рефакторинг |
|---|---|---|---|
| 0.0 – 0.3 | много | мало | нет |
| 0.3 – 0.6 | средне | средне | мало |
| 0.6 – 0.8 | мало | много | средне |
| 0.8 – 1.0 | почти нет | дохуя | много |

### Задачи

У каждой таски есть базовые параметры. Статы разраба применяются как множители.

| Параметр | Описание |
|---|---|
| `task_name` | Название |
| `task_type` | FEATURE / BUG / REFACTOR |
| `complexity` | Сложность — влияет на время выполнения |
| `reward` | Базовые деньги (только FEATURE) |
| `debt_delta` | Базовое изменение техдолга (+ или −) |
| `penalty` | Штраф деньгами если истекла (только BUG) |
| `deadline` | Время до истечения |

**FEATURE** — выполнил → `reward * quality` денег. Истекла — просто исчезла.

**BUG** — выполнил → ничего. Истек — `penalty` деньгами + `+0.1` техдолга.

**REFACTOR** — выполнил → `-debt_delta * quality` техдолга. Денег не даёт. Истек — просто исчез.

## Core Loop

1. Начало спринта — генерируется пак задач (состав зависит от техдолга)
2. Перетаскиваешь задачи на разрабов
3. Разраб выполняет задачу, применяются эффекты через его статы
4. Техдолг растёт/падает, деньги зарабатываются/штрафуются
5. → следующий спринт

## Экран

**Сверху:** очередь задач — горизонтальная полоса с карточками. На каждой карточке: тип, название, сложность, таймер.

**Снизу:** офис со столами. Перетащил карточку на разраба — он начал работать, прогресс-бар тикает.

**HUD:** деньги и шкала техдолга.
