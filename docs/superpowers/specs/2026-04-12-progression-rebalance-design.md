# Progression Rebalance Design

## Context

Текущая система прогрессии сломана:
- Уровни слишком частые в начале (экспоненциальная XP кривая `30 * 1.5^level` даёт первые 5 уровней за минуту)
- Апгрейды слишком мощные (×2.0, ×3.0 мультипликаторы ломают баланс за 2 клика)
- Нет прогрессии внутри апгрейдов — все доступны сразу, нет ощущения роста
- Спринтовая система усложняет скейлинг
- Капитализация не доходит до больших чисел (фантазия стартапа — от тысяч до триллиона)

---

## 1. Якоря баланса

Фиксированные параметры из которых выводится всё остальное:

| Якорь | Значение | Описание |
|-------|----------|----------|
| TTK | 3 сек | Один дев убивает одну таску за 3 сек при нормальной прокачке |
| Время рана | 600 сек (10 мин) | `BASE_TOTAL_GAME_TIME` |
| Целевая капитализация | 1 триллион | К концу рана |
| Уровней тасков | 10 | Новый уровень каждую минуту |
| Уровней игрока | 25 | Лвл-ап каждые ~24 сек |
| Девов | 9 | Первый на уровне 0, остальные 8 по найму |
| Апгрейдов за ран | 25 | На хайр-уровнях даётся и хайр, и апгрейд |
| BASE_DAMAGE | 10 | Стартовый урон за удар |
| base_attack_speed | 2.0 сек | Стартовый интервал атаки |
| Speed cap | 0.1 сек | Минимальный интервал атаки |

Стартовый DPS одного дева: `10 / 2.0 = 5`

## 2. Таски

### Убираем спринты

Спринтов больше нет. Таски имеют уровень от 1 до 10. Каждый дев берёт первую таску из очереди и бьёт её в одиночку.

### Task Bag

1. Генерим **task bag** — пул из 10 тасков текущего уровня
2. Из task bag докидываем таски в очередь по мере освобождения места
3. Task bag опустел → генерим новый task bag (уровень определяется текущим временем)

### Уровень тасков по времени

```gdscript
const TASK_LEVEL_THRESHOLDS: Array[float] = [
    BASE_TOTAL_GAME_TIME * 0.0,   # lvl 1  → 0 сек
    BASE_TOTAL_GAME_TIME * 0.1,   # lvl 2  → 60 сек
    BASE_TOTAL_GAME_TIME * 0.2,   # lvl 3  → 120 сек
    BASE_TOTAL_GAME_TIME * 0.3,   # lvl 4  → 180 сек
    BASE_TOTAL_GAME_TIME * 0.4,   # lvl 5  → 240 сек
    BASE_TOTAL_GAME_TIME * 0.5,   # lvl 6  → 300 сек
    BASE_TOTAL_GAME_TIME * 0.6,   # lvl 7  → 360 сек
    BASE_TOTAL_GAME_TIME * 0.7,   # lvl 8  → 420 сек
    BASE_TOTAL_GAME_TIME * 0.8,   # lvl 9  → 480 сек
    BASE_TOTAL_GAME_TIME * 0.9,   # lvl 10 → 540 сек
]
```

### HP тасков (производная от TTK)

HP рассчитывается из ожидаемого DPS дева × TTK (см. секцию "Поминутный расчёт баланса"). Хранятся в константах, подбираются при плейтесте:

```gdscript
const BASE_HP: int = 100

const TASK_HP_MULTIPLIERS: Array[int] = [
    # Значения из таблицы поминутного расчёта
    # Подбираются при плейтесте
]
```

Награда за таск = его HP (капитализация). На таске UI показывает уровень.

## 3. XP кривая

25 уровней за ран. Трешхолды — производная от наград за таски. Цель: лвл-ап каждые ~24 секунды при нормальной прокачке. Задаются вручную:

```gdscript
const XP_BASE: int = 100

const LEVEL_THRESHOLDS: Array[int] = [
    XP_BASE * 0,       # lvl 1
    XP_BASE * 2,       # lvl 2
    XP_BASE * 5,       # lvl 3
    # ... до lvl 25, подбираются при плейтесте
]
```

Меняешь `XP_BASE` — двигаешь всю кривую разом.

## 4. Тирная система апгрейдов

### Рарити

```gdscript
enum UpgradeRarity { COMMON, UNCOMMON, RARE, EPIC, LEGENDARY }
```

**Damage множители:**

| Рарити | Множитель | Цвет рамки |
|--------|-----------|------------|
| Common | ×3 | Серый |
| Uncommon | ×5 | Зелёный |
| Rare | ×9 | Синий |
| Epic | ×15 | Фиолетовый |
| Legendary | ×25 | Оранжевый |

Полная damage цепочка: `3 * 5 * 9 * 15 * 25 = 50,625×`

**Speed множители:**

| Рарити | Множитель |
|--------|-----------|
| Common | ×1.10 |
| Uncommon | ×1.20 |
| Rare | ×1.30 |
| Epic | ×1.40 |
| Legendary | ×1.50 |

Полная speed цепочка: `1.10 * 1.20 * 1.30 * 1.40 * 1.50 = 3.60×`
Две цепочки (global + dev): `3.60 * 3.60 = 12.96×`
Минимальный интервал при макс прокачке: `2.0 / 12.96 = 0.154 сек` (cap 0.1 не достигается)

### Структура данных

Каждый тир — отдельный `.tres` файл. `UpgradeData` получает новое поле:

```gdscript
@export var rarity: UpgradeRarity = UpgradeRarity.COMMON
```

Prerequisites связывают тиры в цепочку:

```
regular_speed_common.tres    → prerequisites: []
regular_speed_uncommon.tres  → prerequisites: [regular_speed_common]
regular_speed_rare.tres      → prerequisites: [regular_speed_uncommon]
regular_speed_epic.tres      → prerequisites: [regular_speed_rare]
regular_speed_legendary.tres → prerequisites: [regular_speed_epic]
```

Каждый .tres имеет уникальное название и описание (не связанные тематически между тирами). Названия — контент, придумываются при реализации.

### Цепочки апгрейдов

7 цепочек × 5 тиров = 35 .tres файлов:

| Цепочка | Тип | Стат | Множители | Влияет на |
|---------|-----|------|-----------|-----------|
| Global Damage | GLOBAL | DAMAGE | ×3/5/9/15/25 | Урон всех девов |
| Global Speed | GLOBAL | SPEED | ×1.1/1.2/1.3/1.4/1.5 | Скорость всех девов |
| Regular Damage | DEV | DAMAGE | ×3/5/9/15/25 | Урон regular |
| Regular Speed | DEV | SPEED | ×1.1/1.2/1.3/1.4/1.5 | Скорость regular |
| Senior Damage | DEV | DAMAGE | ×3/5/9/15/25 | Урон senior |
| Vibecoder Damage | DEV | DAMAGE | ×3/5/9/15/25 | Урон vibecoder |
| Game Duration | GLOBAL | GAME_DURATION | ×3/5/9/15/25 | Длительность рана |

### Стакание

Мультипликативное. Формулы:

```gdscript
damage = BASE_DAMAGE * task_mult * global_damage_mult * dev_damage_mult
attack_interval = base_attack_speed / (global_speed_mult * dev_speed_mult)
attack_interval = max(attack_interval, SPEED_CAP)  # cap 0.1 сек
DPS = damage / attack_interval
```

### Пул на лвл-апе

- На хайр-уровнях игрок получает и нового дева, и выбор апгрейда
- Из пула доступны только апгрейды, чьи prerequisites выполнены
- Полностью прокачанные цепочки (legendary взят) выпадают из пула
- Показываем **3 карточки** на выбор
- Карточка: иконка, уникальное название, описание, множитель, рамка цвета рарити

## 6. Математика скейлинга

### Цепочка расчёта констант (делаем руками до реализации, не в рантайме)

```
TTK (якорь, 3 сек)
  → стартовый DPS (5, из BASE_DAMAGE и base_attack_speed)
    → ожидаемый DPS на минуте N (из количества девов и взятых апгрейдов)
      → HP таски уровня N = DPS × TTK → записываем в TASK_HP_MULTIPLIERS
        → награда за таску = HP → считаем сколько капитализации за минуту
          → XP трешхолды → записываем в LEVEL_THRESHOLDS
```

### Поминутный расчёт баланса

Сбалансированный билд: Global Damage (5) + Global Speed (5) + Regular Damage (5) + Senior Damage (5) + Vibecoder Damage (5) = 25 апгрейдов. Regular Speed и Game Duration не взяты.

| Мин | Девов | Кум. апгр. | Что взяли за минуту | Avg DPS/dev | HP таски (DPS×3) |
|-----|-------|------------|---------------------|-------------|------------------|
| 0 | 2 | 2 | global dmg ×3, ×5 | 75 | 225 |
| 1 | 3 | 5 | global spd ×1.1, reg dmg ×3, sen dmg ×3 | 193 | 578 |
| 2 | 4 | 7 | vib dmg ×3, global spd ×1.2 | 297 | 891 |
| 3 | 6 | 10 | global dmg ×9, reg dmg ×5, sen dmg ×5 | 9,801 | 29,403 |
| 4 | 7 | 12 | vib dmg ×5, global spd ×1.3 | 17,388 | 52,164 |
| 5 | 9 | 15 | global dmg ×15, reg dmg ×9, sen dmg ×9 | 1,651,137 | 4,953,412 |
| 6 | 9 | 17 | vib dmg ×9, global spd ×1.4 | 3,284,777 | 9,854,330 |
| 7 | 9 | 20 | global dmg ×25, reg dmg ×15, sen dmg ×15 | 849M | 2.55B |
| 8 | 9 | 22 | vib dmg ×15, global spd ×1.5 | 1.85B | 5.54B |
| 9 | 9 | 25 | reg dmg ×25, sen dmg ×25, vib dmg ×25 | 46.2B | 138.5B |

**Итоговый DPS/dev к концу: ~46.2B**
**HP таски на 10 минуте: ~138.5B**
**Капитализация за последнюю минуту:** 9 × 20 × 138.5B ≈ **25 триллионов**

Перелёт ×25 от цели в 1 триллион при идеальном билде. При неидеальной прокачке и учёте TTK для настройки HP тасков — попадаем в диапазон 1-5 триллионов. Точные значения HP подбираются при плейтесте.

### Saw-tooth паттерн

DPS растёт неравномерно — скачки на минутах 3, 5, 7, 9 когда прилетают жирные damage апгрейды. Между скачками — провалы, когда новый уровень тасков прыгает в HP а DPS ещё не подтянулся. Это создаёт пилообразное ощущение: "блять, не успеваю" → апгрейд → "кайф, разношу" → новый уровень тасков → цикл повторяется.

Vibecoder получает dev-апгрейды с задержкой (чётные минуты), поэтому в нечётные минуты он слабее regular и senior. Это нормально — saw-tooth по типам девов.

## 8. Что удаляется

- Спринтовая система (sprint timer, sprint_number, sprint speed bonus)
- `UpgradeStat.SPRINT_TASK_COMPOSITION`
- `UpgradeStat.SPRINT_DURATION` — заменяется на `GAME_DURATION`
- `difficulty` параметр из тасков
- Старые .tres файлы апгрейдов (7 штук)
- `Balance.scale_task_hp()` — заменяется на `get_task_hp(task_level)`
- `Balance.get_xp_for_level()` — заменяется на lookup в `LEVEL_THRESHOLDS`
- `Constants.XP_BASE` формула `BASE_HP * 0.3` — заменяется на ручной `XP_BASE`
